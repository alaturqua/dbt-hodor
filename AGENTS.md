# AGENTS.md

dbt-hodor is a dbt plugin that decides whether a node is reused or rebuilt. A wrong reuse
leaves stale data that looks fresh, so anything uncertain must build.

## Commands

```sh
uv sync
uv run pytest            # DuckDB only; benchmark, databricks, postgres markers skip by default
uv run ruff check
uv run ruff format
uv run --group docs mkdocs build --strict
```

## Rules

- Follow the `karpathy-guidelines` skill: state assumptions, simplest change, touch only what
  the task needs, define a check and run it.
- Test first. Decision changes get a case in the table-driven tests in `tests/test_engine.py`.
- `engine.py` stays pure: no I/O. Hashing, lineage, metadata and stores live in their own modules.
- Fail open: every failure path ends in a build and never fails the dbt run.
- A changed setting updates `docs/configuration.md`, the `README.md` table and
  `docs/guide/index.html`. A new reason code goes in `docs/how-it-works/decision-rules.md`.
- Docs: plain sentences, no hype, state limits. Claims must match tests that ran. Describe
  what the tool does; do not prescribe CI/CD design.
- Adapter-specific text (profile, data version, limits) goes in `docs/adapters/<adapter>.md`;
  store-specific text goes in `docs/stores/`. Core pages stay adapter-neutral and link there.
- Public repo: no workspace URLs, warehouse ids, catalog names, emails or local paths.
- Conventional Commits (changelog is generated by git-cliff). No AI attribution lines in
  commits or PRs.
- LF line endings, UTF-8.
