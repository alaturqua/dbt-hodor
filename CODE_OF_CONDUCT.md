# Code of conduct

## The short version

Be respectful. Assume the other person is trying to help. Discuss the code, not the person.

## Expected behaviour

- Give and take feedback on the work itself. "This reuses a node that changed, here is the
  case" is useful. "This is terrible" is not.
- Accept that a maintainer may say no to a feature. The scope of this project is narrow on
  purpose, and section 3 of the [design spec](docs/design.md) lists what is deliberately out.
- Respect that people contribute in their own time and in different time zones, and that a
  reply can take a while.

## Unacceptable behaviour

Harassment, insults, discriminatory language, personal or political attacks, publishing
someone's private information, and persistent off-topic disruption after being asked to stop.

## Scope

This applies in issues, pull requests, discussions, commit messages and any other space
belonging to this project, and when representing the project elsewhere.

## Reporting

To reach the maintainer privately, open a draft advisory with the **Report a vulnerability**
button under this repository's Security tab. It is the project's private channel and it works
for a conduct report as well: only you and the maintainer can read it. Describe what happened
and link to it if it is public.

The response may be a warning, removal of a comment, or a block from the repository.

If the report concerns the maintainer, or you would rather not raise it with this project at
all, report the account or repository to GitHub Support with the **Report abuse** link. That
goes to GitHub, not to the maintainer.
